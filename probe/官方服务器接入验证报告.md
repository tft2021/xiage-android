# xiaozhi.me 官方服务器第三方客户端接入验证报告

- 验证时间：2026-08-31
- 验证方式：按 `78/xiaozhi-esp32` 源码（`main/ota.cc`、`main/system_info.cc`、`docs/websocket.md`）复现协议，直接对官方线上服务发真实请求
- 探测脚本：`xiaozhi_probe.py`（可复跑）

---

## 一、结论速览

| 环节 | 结果 | 说明 |
|---|---|---|
| OTA 配置下发 | 放行 | 任意伪造 Device-Id / Client-Id 均可拿到完整配置 |
| WebSocket HTTP 握手 | 放行 | 返回 `101 Switching Protocols` |
| WebSocket 会话建立 | **拒绝** | 发完 `hello` 后服务端立即 Close |
| MQTT 连接 | 放行但无实效 | `CONNACK 0`（接受），但 `subscribe_topic = "null"` |
| 激活端点 | **分情况** | 新设备 `202` 等待绑定；已注册设备 `200` 已激活 |

**总体结论：官方服务器不排斥第三方客户端，但以「是否在 xiaozhi.me 完成账号绑定」为门槛。未绑定的设备只能拿到测试组占位凭据，无法进入实际对话。**

安卓 App 可以完成绑定流程（把 ESP32 屏幕上的 6 位码换成 App 界面显示），因此**接入官方服务器是可行的**。

## 二、服务端关键地址

| 用途 | 地址 |
|---|---|
| OTA / 配置下发 | `https://api.tenclass.net/xiaozhi/ota/` |
| 激活确认 | `https://api.tenclass.net/xiaozhi/ota/activate` |
| WebSocket | `wss://api.tenclass.net/xiaozhi/v1/` |

## 三、踩到的第一个坑：User-Agent 必须合规

服务端会解析 `User-Agent` 校验板型与版本号，格式不符直接 400。

真实格式（`main/system_info.cc`）：

```cpp
std::string SystemInfo::GetUserAgent() {
    auto app_desc = esp_app_get_description();
    return std::string(BOARD_NAME "/") + app_desc->version;
}
```

即 `{BOARD_NAME}/{version}`。实测：

| User-Agent | 结果 |
|---|---|
| `Xiaozhi/1.7.2` | 200 |
| `Xiaozhi/2.2.2 (esp32s3) IDF/v5.4.0` | **400 Invalid board type or app version** |

板型名本身不做白名单校验 —— `android-phone/1.7.2`、`lichuang-c3-dev/1.7.2` 均返回 200。
**安卓客户端直接用 `YourBoardName/1.7.2` 即可。**

请求头完整清单（`main/ota.cc` 的 `SetupHttp()`）：

```
Activation-Version  1（无序列号）或 2（有 eFuse 序列号）
Device-Id           设备 MAC
Client-Id           软件 UUID
Serial-Number       仅 Activation-Version=2 时携带
User-Agent          {BOARD_NAME}/{version}
Accept-Language     zh-CN
Content-Type        application/json
```

```json
{
  "server_time": {"timestamp": 1788185775581, "timezone_offset": 480},
  "firmware": {"version": "1.7.2", "url": ""},
  "mqtt": {
    "endpoint": "api.tenclass.net",
    "client_id": "GID_test@@@aa_bb_cc_dd_ee_30@@@2f43176d-...",
    "username": "eyJpcCI6IjExNy4xNTEuOTcuMTIwIiwiYyI6MH0=",
    "password": "Pjpg3SWja4Hw56wSRclfOHe1fKkZvJ/hK8jbj0HZnLs=",
    "publish_topic": "device-server",
    "subscribe_topic": "null"
  },
  "websocket": {
    "url": "wss://api.tenclass.net/xiaozhi/v1/",
    "token": "test-token"
  },
  "activation": {
    "code": "997945",
    "message": "xiaozhi.me\n997945",
    "challenge": "170af108-bd08-4bb7-b644-5b77ac9834a5"
  }
}
```

三处证据指向「未绑定状态」：

1. `client_id` 前缀 **`GID_test`** —— 测试组，而非真实设备组
2. `subscribe_topic` 为字符串 **`"null"`** —— 未分配订阅主题，收不到任何服务端下发
3. `websocket.token` 恒为 **`"test-token"`** —— 占位符

补充观察：`mqtt.username` 是 Base64，解码后为 `{"ip":"117.151.97.120","c":0}`，其中 `c` 疑似绑定标志（未绑定 `0`，已注册设备为 `1`）。

固件的消费方式（`main/ota.cc`）：`websocket` 段不做字段名硬编码，而是遍历所有键值对写入 `Settings("websocket")` 命名空间，所以服务端换成 `access_token` 之类的键名固件也能自适应。

## 五、WebSocket 实测

握手请求：

```
GET /xiaozhi/v1/ HTTP/1.1
Host: api.tenclass.net
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Key: <random>
Sec-WebSocket-Version: 13
Authorization: Bearer test-token
Protocol-Version: 1
Device-Id: AA:BB:CC:DD:EE:01
Client-Id: <uuid>
```

响应：

```
HTTP/1.1 101 Switching Protocols
Server: nginx/1.24.0
Sec-WebSocket-Accept: 6/P4c7vtNQ43QguPBHyHnsfcIy8=
```

发送 `hello` 后：

```
>>> {"type":"hello","version":1,"features":{"mcp":true},"transport":"websocket",
     "audio_params":{"format":"opus","sample_rate":16000,"channels":1,"frame_duration":60}}
<<< Close frame, code=0, reason=""
```

**101 是 nginx 层返回的，不代表应用层接受。** 会话在 `hello` 之后立刻被关闭，说明 `test-token` 不是有效凭据。

## 六、激活端点实测

`POST https://api.tenclass.net/xiaozhi/ota/activate`

固件在**无 eFuse 序列号**时，`GetActivationPayload()` 直接返回 `{}`：

```cpp
if (!has_serial_number_) {
    return "{}";
}
```

这正是 DIY 板子和手机客户端要走的路径 —— 不需要 HMAC 硬件密钥。

实测结果：

| 设备 | 响应 | 含义 |
|---|---|---|
| 全新随机 Device-Id | `202 {"message":"Device activation timeout"}` | 等待用户在网页输入 6 位码 |
| `AA:BB:CC:DD:EE:01` | `200 {"message":"Device activated","device_id":1763214}` | 已激活 |

固件对状态码的处理（`main/ota.cc`）：

- `200` → `ESP_OK`，激活成功
- `202` → `ESP_ERR_TIMEOUT`，继续等待/重试
- 其他 → `ESP_FAIL`

**注意**：即便 `AA:BB:CC:DD:EE:01` 返回了激活成功，它后续的 OTA 响应里 `token` 仍是 `test-token`、`subscribe_topic` 仍是 `"null"`。说明该 Device-Id 虽被系统登记，但**没有绑定到真实用户账号**，因此仍停留在测试组。

## 七、安卓客户端接入官方服务器的推荐流程

1. 生成并持久化一对固定的 `Device-Id`（可用 `Settings.Secure.ANDROID_ID` 或自造 UUID 格式 MAC）与 `Client-Id`（UUID），写进 SharedPreferences，**卸载前保持不变**
2. 带 `Activation-Version: 1` 调 OTA，拿到 `activation.code`（6 位）
3. 在 App 界面显示这 6 位码，引导用户去 xiaozhi.me 登录并输入绑定
4. 轮询 `/activate`（空载荷 `{}`），202 继续等，200 表示绑定完成
5. 重新调 OTA，此时应拿到真实 `token` 与真实 `subscribe_topic`
6. 用真实 token 建 WebSocket / MQTT 会话

第 5 步我无法自动验证（需要真人账号登录），但从 `GID_test`、占位 token、`subscribe_topic: null` 三处一致的证据推断，绑定成功后这些字段会被替换为真实值。

## 八、风险与注意事项

1. **官方从未公开承诺支持第三方客户端**，现有放行属于协议开放的自然结果，随时可能增加校验（例如校验 MAC 的 OUI、UA 白名单、请求频率）。本次已能观察到服务端对 UA 格式的强校验。
2. **稳定性风险**：商业产品依赖官方服务器存在被限流或封禁的可能。
3. **合规风险**：用第三方客户端消耗官方免费额度，需自行评估是否符合其服务条款。
4. **稳妥替代方案**：自建服务端。开源实现有三个成熟选择：
   - Python：`xinnan-tech/xiaozhi-esp32-server`（最活跃）
   - Java：`joey-zhou/xiaozhi-esp32-server-java`
   - Go：`AnimeAIChat/xiaozhi-server-go`、`hackers365/xiaozhi-esp32-server-golang`
